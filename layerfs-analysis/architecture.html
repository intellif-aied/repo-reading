Mutable workspaces, immutable filesystem roots

The host coordinates sessions and owns canonical storage. Filesystem projections expose a working view; Commit freezes its changes and publishes a checked Branch update.

A commit crosses two boundaries

First, pause and quiesce the projection. Capture ordinary files or obtain frozen FUSE facts, then use the host content algorithms to build a new namespace root. Unchanged objects keep their identities.

Next, admit objects and retain a workspace stage. The Store checks the expected Branch head and base before advancing history. Checkpoint installation and projection recovery follow publication; a successful Commit can still report a failed presentation.

Follow walkthrough sections 18–21 and lifecycle.rs.

Where the detail lives

The portable core models names, inodes, pieces, revisions and resource charges. FUSE and host adapters own synchronization and physical backing. The container does not own the SQLite Store.
